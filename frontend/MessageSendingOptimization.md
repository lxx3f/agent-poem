# 前端消息发送优化说明

## 问题描述
前端发送消息后会等待后端响应，但由于后端需要处理LLM调用，响应较慢，导致前端出现等待超时提示。

## 解决方案

### 1. 增加请求超时时间
**文件**: `src/utils/request.ts`
- 将axios请求超时时间从20秒增加到60秒
- 适应LLM处理时间较长的特点

### 2. 实现乐观更新 (Optimistic Update)
**文件**: `src/components/MessageInput.vue`, `src/views/Chat.vue`, `src/components/MessageList.vue`

#### 主要改进：
- **即时反馈**: 用户发送消息后立即在界面上显示，无需等待后端响应
- **视觉区分**: 乐观消息带有虚线边框和脉冲动画，区别于已确认的消息
- **状态管理**: 添加"发送中..."状态指示器和动态文本提示

#### 实现细节：
- MessageInput组件新增`optimistic-message`事件
- Chat组件管理乐观消息数组
- MessageList组件展示合并的真实消息和乐观消息

### 3. 增强加载状态指示
**文件**: `src/components/MessageInput.vue`

#### 特性：
- **动态发送文本**: "发送中..." → "AI思考中..." → "正在检索..." → "整理回复中..."
- **加载提示**: 1秒后显示"AI正在思考中，请稍候..."
- **旋转动画**: 发送按钮上的加载spinner动画

### 4. 错误处理和重试机制
**文件**: `src/components/MessageInput.vue`

#### 特性：
- **智能错误提示**: 根据不同错误类型提供具体提示
- **一键重试**: 错误消息旁显示重试按钮
- **错误分类**:
  - 超时错误: "请求超时，请检查网络连接或稍后重试"
  - 认证错误: "认证已过期，请重新登录"
  - 其他错误: 显示具体错误信息

### 5. 用户体验优化

#### 视觉反馈：
- 加载动画和状态指示器
- 消息气泡的不同样式（用户/AI/系统）
- 平滑的过渡动画

#### 交互优化：
- 自动滚动到最新消息
- Enter键快速发送（Shift+Enter换行）
- 文本域高度自适应

## 技术实现要点

### 类型定义
```typescript
interface OptimisticMessage {
  id: string;
  content: string;
  role: 'user' | 'assistant';
  timestamp: string;
  status: 'sending' | 'sent';
}
```

### 核心逻辑流程
1. 用户点击发送 → 立即触发乐观更新
2. 显示"发送中..."状态和加载动画
3. 调用后端API
4. 成功后清除乐观消息，显示真实消息
5. 失败时显示错误信息和重试选项

## 注意事项

1. **数据一致性**: 乐观更新只是UI层面的优化，最终仍需依赖后端确认
2. **错误边界**: 确保在网络异常情况下能正确回滚UI状态
3. **用户体验**: 避免过度的动画效果影响性能
4. **可访问性**: 确保屏幕阅读器能正确读取状态变化

## 后续优化方向

1. **离线支持**: 实现消息队列，支持断网重连
2. **进度指示**: 更详细的任务进度反馈
3. **智能重试**: 根据错误类型自动重试
4. **缓存优化**: 本地缓存常用数据减少请求
